# 合并后审查修复

对应 FIX-1 至 FIX-4，作为独立修复 PR 交付，不回滚 v0.1.1。仅覆盖当前问题的必要检查，没有新增付费模型调用。

## FIX-1：确认和执行同一版本

任务详情返回 `workflow_digest`（完整工作流的 SHA-256，包含步骤审核状态）。工作台保存自己实际展示版本的摘要，不从更新后的任务元数据替换确认摘要。

| 请求 | 必需内容 | 返回 |
| --- | --- | --- |
| `GET /api/tasks/ID` | 无 | `workflow`、`workflow_digest` |
| `PUT /api/tasks/ID/workflow` | `{workflow, expected_digest}` | `{workflow, workflow_digest}`；保存后步骤待审核 |
| `POST /api/tasks/ID/approve` | `{expected_digest}` | `{workflow, workflow_digest}`；使用新摘要发起执行 |
| `POST /api/tasks/ID/execute` | `{expected_digest, parameters?, confirm_sensitive?}` | 202；执行通过摘要检查的内存快照 |

缺少摘要返回 422；版本冲突返回 409，响应 `code: workflow_conflict`。冲突不会批准、保存或启动新版本。工作台停止确认并提供“加载最新流程”。没有本地修改或确认弹窗时，轮询会正常加载新版本；有待确认内容时要求重新核对。旧版本执行报告不能显示为当前版本的完成结果。

复用 FileLock，让 CLI 与 API 的工作流写入共用跨进程锁；有 `expected_digest` 的比较与替换在同一锁内进行。CLI 的交互审核也检查用户看到的版本。直接用外部编辑器写文件不会遵守此锁，因此不宣称支持任意外部写入的事务隔离；执行快照仍不会被后来磁盘上的工作流替换。任务执行/分析排队仍为单 API 进程，尚未提供多 worker 调度。

## FIX-2：来源与执行成功分别标记

`workflow_origin` 由服务端提供，列表与详情使用相同规则：

- `manual`：CLI 导入明确记录的人工流程。
- `video`：模型成功收据、生成快照、原始响应、帧清单与源摘要记录一致，当前流程除审核状态外未改变。
- `video_edited`：具有上述生成记录，之后改动过步骤、待确认项或其他内容。
- `unknown`：旧数据没有来源记录、记录不完整或摘要不一致。

不再用标题和文件名猜测来源。此标签说明生成记录，**不等于真实逆向验收通过**，也不构成第三方签名。轮询不重复读取整个媒体/全部图片；需要核验实际文件字节及执行闭环时，使用 `replaylab validation-report`。

## FIX-3：有界媒体获取

继续复用 yt-dlp 的站点解析和下载器，附加受限 urllib 传输适配器。锁定版本下验证过该适配器；升级 yt-dlp 时应保留其回归检查。

- 入口及每次后续 HTTP(S) 请求/重定向均要求 DNS 结果全部为公网地址；拒绝凭据 URL、私网、loopback、link-local、共享/保留地址、组播和地址转换前缀。
- 独立进程中的 Python socket 审计钩子再次检查实际连接地址，阻止 DNS 检查后转为内网的连接；拒绝外部下载器子进程。
- 单次获取累计响应正文不超过 200 MB；已知 Content-Length 提前拒绝，缺少长度的流式读取也计量。只接受 identity 内容编码，避免自动解压逃逸读取预算。
- socket 超时 15 秒，无自动重试；父进程对整个获取任务设置 120 秒上限，失败/超时清理临时下载文件。
- 目前只下载直接 HTTP(S) 视频格式；不支持 HLS/DASH、播放列表、需外部下载器或 JavaScript 运行时的站点。FFmpeg/ffprobe 仅允许 `file,pipe`，不能从媒体文件继续访问远程链接。
- 检测到系统网络代理时明确拒绝远程获取，提示上传本地视频。代理独立解析目标，本机检查无法约束其转发，不自动移除或绕过代理配置。

这是当前受限的媒体获取入口，不是恶意 Python 插件或恶意编解码器的完整沙箱。上传本地视频和 CLI 本地文件输入继续可用；媒体公网过滤不改变用户明确指定的浏览器执行网址。

## FIX-4：轻量自动检查

[Core checks](../.github/workflows/ci.yml) 在 PR 和 main 推送时运行：锁定依赖安装、Ruff、核心 pytest、Node 22 下的 TypeScript/Vite 构建。单个 Ubuntu/Python 3.12 环境，10 分钟上限、同分支旧任务取消；不下载浏览器、不读取模型密钥、不进行网络模型调用。

本地必要检查：核心原有 10 项与新增 11 项共 21 项回归用例通过；FFmpeg 对现有样本的探测/单帧解码通过，内嵌远程播放列表请求被拒绝。实际工作台另检查来源标签、轮询更新、确认中冲突、旧摘要提交、重新加载及编辑保存/审核/执行请求；该 UI 检查替换执行函数，只验证版本协议，不冒充真实视频或 Agent 执行。

完整兼容、安全与并发压力矩阵继续放在测试待办，由用户提出后开展。GitHub 的实际 Check Run 以 PR 页面为准，本地检查不替代远程检查状态。
